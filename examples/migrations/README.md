# Migration and Schema Examples

This directory demonstrates CQL's powerful migration system and schema management capabilities. Learn how to evolve your database schema safely while maintaining up-to-date Crystal schema definitions.

## 📝 Examples Overview

### 🔄 **schema_migration_workflow.cr**

**Purpose:** Complete migration workflow demonstration using SQLite
**Features:**

- Integrated schema migration system with auto-synchronization
- Step-by-step migration process (up, rollback, redo)
- Automatic schema file generation and updates
- Schema consistency verification
- Team workflow scenarios
- Development vs production configuration patterns

**Run:** `crystal schema_migration_workflow.cr`
**Database:** SQLite (no external dependencies)

### 🐘 **schema_migration_workflow_pg.cr**

**Purpose:** PostgreSQL-specific migration workflow
**Features:**

- PostgreSQL migration patterns and best practices
- Advanced PostgreSQL features (JSONB, arrays, UUID)
- Production deployment workflows
- Environment-specific PostgreSQL configuration
- SSL and advanced connection options

**Run:** `crystal schema_migration_workflow_pg.cr`
**Prerequisites:** PostgreSQL server running
**Environment Variable:** `DATABASE_URL` (optional, defaults to localhost)

### 📋 **generated_schema.cr**

**Purpose:** Example of auto-generated schema file
**Features:**

- Shows the structure of generated schema files
- Demonstrates how migrations update schema definitions
- Example of migration tracking table structure

**Note:** This file is generated by the migration examples

## 🔧 Migration Workflow

### Development Workflow

```crystal
# 1. Create migration
class AddEmailToUsers < CQL::Migration(5)
  def up
    schema.alter :users do
      add_column :email, String
    end
  end

  def down
    schema.alter :users do
      drop_column :email
    end
  end
end

# 2. Apply migration
migrator.up

# 3. Schema file automatically updated
# src/schemas/app_schema.cr now includes email column
```

### Production Deployment

```crystal
# 1. Configure for production
config = CQL::MigratorConfig.new(
  auto_sync: false,  # Manual control in production
  verify_schema: true
)

# 2. Apply migrations
migrator.up

# 3. Verify consistency
migrator.verify_schema_consistency

# 4. Deploy application with updated schema
```

## 🛡️ Best Practices

### Migration Safety

- **Test migrations** - Always test in development first
- **Backup databases** - Backup before production migrations
- **Rollback plans** - Ensure every migration can be rolled back
- **Data validation** - Verify data integrity after migrations

### Schema Management

- **Incremental changes** - Make small, focused migrations
- **Documentation** - Comment complex migrations
- **Naming conventions** - Use descriptive migration names
- **Version control** - Commit schema files with migrations

### Team Workflows

- **Code reviews** - Review migrations like any other code
- **Communication** - Announce breaking schema changes
- **Coordination** - Coordinate database changes with deployments

## 🚨 Common Scenarios

### Adding a New Table

```crystal
class CreatePosts < CQL::Migration(3)
  def up
    schema.table :posts do
      primary :id, Int64, auto_increment: true
      column :title, String, null: false
      column :content, String
      column :user_id, Int64
      timestamps

      foreign_key [:user_id], references: :users, references_columns: [:id]
      index [:user_id]
    end

    schema.posts.create!
  end

  def down
    schema.posts.drop!
  end
end
```

### Modifying Existing Schema

```crystal
class AddIndexToUsers < CQL::Migration(4)
  def up
    schema.alter :users do
      add_column :active, Bool, default: true
      create_index :active_users_idx, [:active]
    end
  end

  def down
    schema.alter :users do
      drop_index :active_users_idx
      drop_column :active
    end
  end
end
```

### Data Migration

```crystal
class MigrateUserData < CQL::Migration(6)
  def up
    # Schema change
    schema.alter :users do
      add_column :full_name, String
    end

    # Data migration
    schema.exec(<<-SQL)
      UPDATE users
      SET full_name = first_name || ' ' || last_name
      WHERE first_name IS NOT NULL AND last_name IS NOT NULL
    SQL
  end

  def down
    schema.alter :users do
      drop_column :full_name
    end
  end
end
```

## 🔗 Integration with Applications

### Using Generated Schemas

```crystal
# After migrations, use the generated schema
require "./src/schemas/app_schema.cr"

# Type-safe database operations
users = AppSchema.query.from(:users).all
posts = AppSchema.query.from(:posts).where(published: true).all
```

### Deployment Integration

```crystal
# In your deployment script
migrator = AppSchema.migrator(production_config)

# Check for pending migrations
if migrator.pending_migrations.any?
  puts "Applying #{migrator.pending_migrations.size} migrations..."
  migrator.up
else
  puts "Database is up to date"
end

# Verify everything is consistent
unless migrator.verify_schema_consistency
  raise "Schema consistency check failed!"
end
```

Before, they ran on any exception: also (a) after the block ended the transaction itself (`tx.commit`/`tx.rollback`, then raised), (b) after a COMMIT whose outcome is unknown (reply lost: ConnectionLost; QueryTimeout), (c) a raising hook stopped the older hooks and replaced the transaction's own error, and (d) `transaction(tx)` with a transaction on another connection attached its hooks to the enclosing frame of this schema. Now: (a) skip when the block ended it; (b) when the failure came from COMMIT (the block finished), run the hooks only if the dialect says that error is a refusal (a server error answer, CQL's `TransactionAborted`, or `ConnectionClosed`: nothing sent) — `Dialect#commit_refused?(error)`, false by default (unknown: keep the state); (c) every hook runs, a raising one is logged; (d) shared hooks only on the same connection. `Schema#on_rollback(&)` becomes public.

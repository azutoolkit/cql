# Use UUID and ULID Primary Keys

This guide shows you how to use UUIDs or ULIDs instead of auto-incrementing integers as primary keys.

CQL generates the key in your application, before the `INSERT`, and stores it as text. That works the same on SQLite, PostgreSQL, MySQL and CockroachDB.

| Model type parameter | Key you see in Crystal | Generated by | Stored as |
| --- | --- | --- | --- |
| `Model(Int32)` / `Model(Int64)` | `Int32?` / `Int64?` | the database (auto-increment) | integer |
| `Model(UUID)` | `UUID?` | `UUID.random` | text, 36 characters |
| `Model(String)` | `String?` | `CQL::ULIDCompat.generate` | text, 26 characters |

## UUID Keys

### 1. Define the Table

The column is a non-incrementing `String` primary key:

```crystal
MyDB = CQL::Schema.define(:my_db, adapter: CQL::Adapter::SQLite, uri: "sqlite3://db/app.db") do
  table :sessions do
    primary :id, String, auto_increment: false # UUID stored as text
    text :token
    bigint :user_id
    timestamps
  end
end
```

### 2. Define the Model

```crystal
class Session
  include CQL::ActiveRecord::Model(UUID)
  db_context MyDB, :sessions

  property token : String = ""
  property user_id : Int64 = 0_i64
  property created_at : Time?
  property updated_at : Time?

  def initialize
  end

  def initialize(@token : String, @user_id : Int64)
  end
end
```

You do not declare `id`. CQL adds it for you, typed as `UUID`, and keeps the text form internally.

### 3. Use It

```crystal
session = Session.create!(token: "abc", user_id: 1_i64, created_at: Time.utc, updated_at: Time.utc)

session.id    # => UUID?
session.id!   # => UUID, raises if the record has no id yet
session.id?   # => UUID?

Session.find!(session.id!)
Session.query.where { id == session.id! }.to_a
Session.find_or_create_by(token: "abc")
```

`id=` takes a `UUID`. Do not assign an id before `create!`: it is generated and any `:id` you pass is dropped.

## ULID Keys

A ULID is a 26-character, time-ordered identifier, so new rows sort after old ones. Use a `String` key type:

```crystal
table :events do
  primary :id, String, auto_increment: false # ULID stored as text
  text :event_type
  text :payload
  timestamps
end

class Event
  include CQL::ActiveRecord::Model(String)
  db_context MyDB, :events

  property event_type : String = ""
  property payload : String = ""
  property created_at : Time?
  property updated_at : Time?

  def initialize
  end

  def initialize(@event_type : String, @payload : String)
  end
end

event = Event.create!(event_type: "user.created", payload: "{}", created_at: Time.utc, updated_at: Time.utc)
event.id!        # => "01HZX3Q8N5V2K7R4M9PB6TCD1E" (26 characters)
```

`CQL::ULIDCompat.generate` builds the value: 10 characters of millisecond timestamp followed by 16 random characters, in Crockford base32. Things to know:

- Ids made in different milliseconds sort by creation time. Ids made in the same millisecond are random relative to each other.
- It is not a cryptographic generator. Do not use a ULID as a secret token.
- Every `Model(String)` generates a ULID on `create!`. If you need to supply your own string keys (slugs, external ids), declare a different key column and keep an integer or UUID primary key.

## Rollbacks Waste Ids

The id is generated before the `INSERT`. If the surrounding transaction rolls back, that id is simply never used. With 128-bit ids this is harmless, and integer keys avoid it only because the database assigns them.

```crystal
MyDB.transaction do |tx|
  Session.create!(token: "abc", user_id: 1_i64) # id generated here
  tx.rollback                                   # id is discarded
end
```

## Associations on a UUID Key

A `has_many` or `has_one` owned by a UUID-keyed model binds the owner's id as text, so its queries and its
[`dependent:` strategies](../relationships/has-many.md#when-the-parent-is-deleted) work as they do for integer keys. So do a
`many_to_many`'s queries, its join-row cleanup when the owner is deleted, and `dependent: :destroy`; its `:delete_all`,
`ids`, `ids=` and `delete(id)` still need the owner and the targets to share a key type. The child's foreign key is typed
`UUID`:

```crystal
class SessionNote
  include CQL::ActiveRecord::Model(Int64)
  db_context MyDB, :session_notes

  @[DB::Field(converter: CQL::UUIDConverter)]
  property session_id : UUID
end

class Session
  include CQL::ActiveRecord::Model(UUID)
  db_context MyDB, :sessions

  has_many :notes, SessionNote, foreign_key: :session_id, dependent: :destroy
end
```

On SQLite the column is text, so read it with `CQL::UUIDConverter`, which does not accept NULL. A model cannot write a
UUID column other than its primary key yet, so `SessionNote.create!(session_id: ...)` and `session.notes.create(...)` do
not compile; insert those rows with `MyDB.insert.into(:session_notes).values(session_id: session.id!.to_s).commit`.

## Typed Queries

Comparisons in the typed `where` DSL accept the `UUID` itself. CQL binds it as text:

```crystal
Session.query.where { id == uuid }.to_a
Session.query.where { id.in([first_uuid, second_uuid]) }.to_a
```

## Schema Mapping Validation

When you run with `CQL_VALIDATE_SCHEMA_MAPPINGS=1`, a `UUID` getter is accepted against a `String` column, so the table definition above passes. See [Dump and Validate Your Schema](../migrations/schema-dump-and-validation.md).

## Converters for Plain Structs

Models handle the conversion for you. For a `DB::Serializable` struct that is not a CQL model, use the converters in `CQL`:

```crystal
struct Token
  include DB::Serializable

  @[DB::Field(converter: CQL::UUIDConverter)]
  property id : UUID
  property label : String
end

struct UserPref
  include DB::Serializable

  property id : Int64
  @[DB::Field(converter: CQL::JSONBConverter)]
  property preferences : JSON::Any
end
```

- `CQL::UUIDConverter.from_rs` reads a text column into a `UUID`; `to_db` turns a `UUID` (or `nil`) back into text.
- `CQL::JSONBConverter.from_rs` reads a `json` / `jsonb` column into `JSON::Any`; `to_db` serializes it with `to_json`.
